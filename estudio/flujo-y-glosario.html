Flujo de peticiones y como interactuan los archivos

Esta guia complementa el manual general. Se enfoca en como viaja cada peticion por el proyecto y en que archivo le pasa la posta a cual, con el codigo real del repositorio como ejemplo.

Mapa de archivos: quien depende de quien

navegador (HTML + fetch) | | peticion HTTP (GET/POST) v server.js ---- require('./controllers') ----> controllers.js | | require('./model') v model.js (datos en memoria) server.js ---- res.render('topics') --------> views/topics.ejs | | <script src="/app.js"> v public/app.js (corre en el navegador)

server.js es el unico archivo que conoce las rutas. controllers.js es el unico que conoce req y res. model.js es el unico que toca el array de datos. Cada capa solo habla con la de al lado, nunca se salta una.

Patron a notar: las acciones que vienen de un <form> normal terminan en res.redirect('/') (recargan la pagina completa). Las acciones que vienen de fetch (votar) terminan en res.json(...) (no recargan nada, solo mandan datos).

1. server.js habla con controllers.js

server.js importa el modulo de controladores y conecta cada ruta con su funcion:

server.js

const controllers = require('./controllers')
...
app.post('/topics/:id/vote', controllers.voteTopic)

Express llama a controllers.voteTopic automaticamente cuando llega un POST a esa URL, pasandole req y res como argumentos.

2. controllers.js habla con model.js

El controlador no sabe nada de arrays ni de votos. Solo traduce la peticion HTTP a una llamada de funcion:

controllers.js

const topics = require('./model')

voteTopic: function (req, res) {
    const id = req.params.id
    topics.voteTopic(id)
    res.json(topics.getAllTopics())
}

Y model.js es quien realmente modifica los datos:

model.js

function voteTopic(id){
    const topic = topics.find(t => t.id === parseInt(id))
    if (!topic) return false
    topic.votos = topic.votos + 1
    return true
}

Nota el parseInt(id): req.params.id siempre llega como texto (viene de la URL), aunque en el array los id son numeros. Sin el parseInt, === nunca daria true.

Ejemplo completo: crear un tema

  1. El usuario llena el input name="nombre" y aprieta "Agregar tema" (formulario normal, sin JS).
  2. El navegador manda POST /topics con el body nombre=....
  3. server.js lo enruta a controllers.createTopic.
  4. controllers.js lee req.body.nombre y llama a topics.createTopic(nombre).
  5. model.js empuja un objeto nuevo al array topics con push.
  6. El controlador responde res.redirect('/'): el navegador vuelve a pedir GET / y ve la lista actualizada.

3. views/topics.ejs y public/app.js hablan por fetch

El boton de votar no es un formulario cualquiera: tiene la clase vote-form, y public/app.js escucha todos los submit de la pagina:

public/app.js

document.addEventListener('DOMContentLoaded', () => {
  const list = document.getElementById('topicsList')
  list.addEventListener('submit', function(e){
    if (e.target.classList.contains('vote-form')){
      e.preventDefault()
      fetch(e.target.action, {method: 'POST'})
        .then(res => res.json())
        .then(topics => {
          list.innerHTML = renderTopics(topics)
        })
    }
  })
})

e.preventDefault() es la clave: cancela el envio normal del formulario (que recargaria la pagina) y en su lugar manda la misma peticion por fetch. El controlador responde JSON en vez de HTML, y renderTopics() reconstruye la lista en el navegador sin recargar.

Esto es lo que separa un formulario "normal" (action + method, recarga la pagina) de uno interceptado por JavaScript (misma action, pero el navegador nunca navega).

Glosario: JavaScript (palabras reservadas y conceptos)

Palabra / conceptoQue hace
constDeclara una variable que no se puede reasignar.
letDeclara una variable que si se puede reasignar (usada para el array topics, aunque en la practica solo se mutan sus elementos).
functionDeclara una funcion con nombre, ej: function voteTopic(id) {...}.
Arrow function =>Sintaxis corta para funciones, ej: t => t.id === id.
thisDentro de un callback de Express (function(req,res){...}) no se usa en este proyecto; las funciones son simples.
require(...)Importa un modulo de Node. Ej: require('./model') trae lo que exporta model.js.
module.exportsDefine que "sale" de un archivo cuando otro lo importa con require.
if / return falsePatron usado en model.js: si no se encontro el dato, corta la funcion devolviendo false en vez de lanzar un error.
parseInt(valor)Convierte texto a numero entero. Necesario porque req.params siempre da strings.
Spread [...topics]Crea una copia superficial del array, para no ordenar (sort) el array original por accidente.
Template string `texto ${var}`String con variables interpoladas, usado en public/app.js para armar HTML dinamicamente.

Glosario: Express

Metodo / objetoQue hace
express()Crea la aplicacion Express (const app = express()).
app.set('view engine', 'ejs')Le dice a Express que use EJS para renderizar vistas.
app.use(middleware)Registra una funcion que corre en todas las peticiones antes de llegar a las rutas.
express.urlencoded()Middleware que lee formularios HTML y llena req.body.
express.static(carpeta)Middleware que sirve archivos tal cual (CSS, JS del navegador) desde una carpeta.

res.json(datos)Manda la respuesta como JSON en vez de HTML.
