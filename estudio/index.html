Manual de estudio: CRUD de Temas

Este manual explica los conceptos y el flujo de datos del proyecto CRUD, paso a paso, tomando como base su propio codigo.

Que es un CRUD

CRUD es un acronimo que resume las cuatro operaciones basicas sobre datos:

LetraOperacionEn este proyecto
CCreate (crear)createTopic, createLink
RRead (leer)getAllTopics
UUpdate (actualizar)updateTopic, updateLink
DDelete (borrar)deleteTopic, deleteLink

En este proyecto los datos (topics y sus enlaces) se guardan en memoria, en un array dentro de model.js. Eso significa que se reinician cada vez que se reinicia el servidor (no hay base de datos).

Arquitectura MVC

MVC separa el codigo en tres responsabilidades para que cada archivo tenga una sola razon de existir:

  • Modelo (model.js): guarda los datos y sabe como crearlos, modificarlos y borrarlos. No sabe nada de HTTP.
  • Vista (views/topics.ejs): convierte los datos en HTML para el navegador. No sabe nada de logica de negocio.
  • Controlador (controllers.js): recibe la peticion HTTP, le pide datos o cambios al modelo, y decide que devolver (renderizar la vista o mandar JSON).
Regla practica: si estas escribiendo SQL o manipulando el array de datos, eso va en el modelo. Si estas leyendo req.body o req.params, eso va en el controlador. Si estas escribiendo HTML, eso va en la vista.

Rutas HTTP

Cada accion del usuario dispara una peticion a una ruta especifica. Estas son las que define server.js:

GET  /                                    -> listar temas
POST /topics                              -> crear tema
POST /topics/:id/update                   -> actualizar tema
POST /topics/:id/delete                   -> borrar tema
POST /topics/:id/vote                     -> votar tema
POST /topics/:id/links                    -> crear enlace
POST /topics/:id/links/:linkId/update     -> actualizar enlace
POST /topics/:id/links/:linkId/delete     -> borrar enlace
POST /topics/:id/links/:linkId/vote       -> votar enlace

:id y :linkId son parametros de ruta: partes variables de la URL que Express expone en req.params.

Express y middlewares

Express procesa cada peticion pasandola por una cadena de middlewares antes de llegar al controlador. En server.js:

app.use(express.urlencoded({ extended: true })) // lee formularios y llena req.body
app.use(express.static(path.join(__dirname, 'public'))) // sirve app.js y styles.css

Despues de los middlewares, cada app.get / app.post conecta una ruta con la funcion del controlador que la resuelve.

EJS (vistas)

EJS es un motor de plantillas: permite mezclar HTML con JavaScript para generar HTML dinamico en el servidor.

SintaxisUso
<%= valor %>Imprime un valor escapado (seguro contra HTML malicioso).
<% codigo %>Ejecuta codigo JS sin imprimir nada (loops, ifs).

Ejemplo real de topics.ejs: <% topics.forEach(topic => { %> ... <% }) %> recorre el array y repite el bloque HTML por cada tema.

Flujo de una peticion (request/response)

  1. El navegador manda una peticion HTTP (por ejemplo, un formulario hace POST /topics).
  2. Express la recibe y la pasa por los middlewares (urlencoded, static).
  3. Express busca la ruta que coincide y ejecuta la funcion del controlador asociada.
  4. El controlador lee req.body / req.params y llama a una funcion del modelo.
  5. El modelo modifica el array en memoria y devuelve el resultado.
  6. El controlador responde: o renderiza una vista EJS (res.render), o redirige (res.redirect), o devuelve JSON (res.json).
  7. El navegador recibe la respuesta y actualiza lo que el usuario ve.

Ejemplo completo: votar un tema

Este es el recorrido exacto de un clic en el boton "Votar", de punta a punta:

  1. public/app.js intercepta el submit del formulario con clase vote-form y hace fetch(action, { method: 'POST' }) en vez de dejar que el navegador recargue la pagina.
  2. La peticion llega a POST /topics/:id/vote, definida en server.js.
  3. Express ejecuta controllers.voteTopic, que toma req.params.id.
  4. voteTopic llama a topics.voteTopic(id) en model.js, que busca el tema por id y le suma un voto.
  5. El controlador responde con res.json(topics.getAllTopics()): la lista completa de temas, ya reordenada por votos.
  6. app.js recibe ese JSON y reconstruye el HTML con renderTopics(), reemplazando list.innerHTML.
  7. El usuario ve el contador actualizado y el tema reordenado, sin recargar la pagina.

Glosario rapido

TerminoSignificado
MiddlewareFuncion que se ejecuta en el medio del ciclo peticion-respuesta, antes del controlador.
reqObjeto con todo lo que mando el cliente (parametros, body, headers).
resObjeto para construir la respuesta que vuelve al cliente.
req.paramsValores tomados de la URL (ej: el :id de la ruta).
req.bodyDatos enviados en el cuerpo de la peticion (ej: un formulario).
Archivo estaticoArchivo que Express sirve tal cual (CSS, JS del cliente, imagenes), sin procesarlo.
RenderizarGenerar HTML en el servidor combinando una plantilla (EJS) con datos.
